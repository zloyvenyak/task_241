## Перенаправляем

### 1) Как работают команды `>` и `>>`?
- `>` перенаправляет **stdout** команды в файл; файл создаётся (если не было) или перезаписывается (если был).  
- `>>` перенаправляет **stdout** в файл, но добавляет вывод в конец файла, не стирая старое.

**Пример:**
```
echo "one" > a.txt
echo "two" >> a.txt
cat a.txt
```

### 2) Что такое перенаправление ввода? `stderr`, `stdout`
У программ есть стандартные потоки:
- `stdin` — стандартный ввод (fd 0)
- `stdout` — стандартный вывод (fd 1)
- `stderr` — стандартный вывод ошибок (fd 2)

**Перенаправление** — это когда оболочка меняет, откуда команда читает ввод и куда пишет вывод (например, в файл вместо экрана).

### 3) Вывести содержание файла не используя текстовые редакторы
Через `cat`:
```
cat file.txt
```

### 4) Создать файл с содержимым не используя текстовые редакторы
```
echo "Привет" > file.txt
```


### 5) Перенаправить `stdout` в `stderr` и обратно (пример `kinit`, `ping`, `tracert`)
- `stdout → stderr`:
```
команда 1>&2
```
- `stderr → stdout`:
```
команда 2>&1
```

**Примеры на `ping`:**
```
# stdout -> stderr
ping -c 1 127.0.0.1 1>&2

# stderr -> stdout (ошибка резолва/хоста уйдет в stdout)
ping -c 1 no-such-host 2>&1
```

Сначала `stdout` уходит в файл, затем `stderr` отправляется туда же, куда направлен `stdout`.

### 6) Чем отличаются `stdout` и `stderr`
- `stdout` — “нормальный” результат работы программы.
- `stderr` — ошибки/диагностика (чтобы их можно было отдельно направлять/фильтровать/логировать).

### 7) Что такое `stdin`?
`stdin` — стандартный поток ввода (fd 0), обычно связан с клавиатурой/терминалом, но может быть перенаправлен из файла или из другой команды.

### 8) Как отправить весь вывод команды в пустоту?
**Только stdout в “никуда”:**
```
cmd > /dev/null
```

**И stdout, и stderr в “никуда”:**
```
cmd > /dev/null 2>&1
```
